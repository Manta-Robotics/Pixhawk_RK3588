# 原始坐标控制与输出加减速

当前项目保持 f09dd51 的 HTML/JavaScript、Node.js 和 Python 结构。`uwb_follow.control_input=raw` 时，从 Python 已报告完整接收的原始 DIST/AZ 选择一个新鲜接收器，按安装位置/角度换算船体坐标，直接送入相对 UWB/IMU 控制。卡尔曼可信位置继续用于界面和诊断；坐标突跳不再要求预测器或 NMPC 先建立连续轨迹。`filtered` 保留原有滤波、融合和可选 NMPC 路径。

原始观测的有效时间保持 `receivedMeasurementAt`，元数据、重复时钟和下一帧单独 DIST 不得更新完整观测。数值、无线有效性、接收器、目标身份、IMU、用户停止和解除武装检查仍有效。信号过期停推；只有用户已开启的跟随请求可以从单帧恢复。此旧版协议的时钟表示电脑收到完整观测的时间，不能声称是射频采样时刻或包含了此前 C++ 分支的时钟同步修复。

相对 IMU 原始控制的最终输出现在经过传统双电机限速器。每侧电机按现有 `relative_throttle_accel_percent_s=30`、`relative_throttle_decel_percent_s=45` 逐渐改变需求，转向目标按 `steering_slew_deg_s=9` 逐渐调整。一次 100ms 控制周期，每侧普通加速最多增加 3 个百分点，普通减速最多减少 4.5 个百分点，转向目标最多改变 0.9°。长时间卡顿不会允许一次补上全部变化。

这些值是推进指令变化率；没有可靠航速测量时，不把它们宣称为船体实测 m/s²。近距离、断信号、无效 IMU、解除武装和主动停止立即归零，绕过舒适性斜坡。界面布局和原始/可信位置显示不变。

`test/uwb_raw_control.test.mjs` 用合成原始坐标突跳、左右反转、残缺帧、旧时钟、断信号、单帧恢复和安全停止验证控制路径，不连接真实推进器。
